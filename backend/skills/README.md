# Skills

Agent 的专项能力按目录存放在这里，一个 skill 一个子目录：

```
backend/skills/
├─ README.md              ← 本文件
└─ <skill-name>/
   ├─ SKILL.md            ← 说明：这个 skill 做什么、何时触发
   ├─ handler.py          ← 实现，暴露一个 handler(ctx, **kwargs)
   └─ assets/             ← 该 skill 私有的模板、词典、样例（可选）
```

## 为什么单独一个目录

`app/` 存放的是**平台**：HTTP 路由、调度器、数据库、模型解析。
`skills/` 存放的是**能力**：可以独立增删、彼此不依赖的具体做法。

这两者变化的速度不同。加一个 skill 不应该触碰调度器代码，删一个 skill 也不
应该让 `app/` 出现悬空导入。分开放，边界就写在目录结构上，而不是靠约定。

## 与现有 agent 的关系

现在 `app/doc/agents.py` 里那 8 个 Agent 的提示词逻辑**暂时留在原地**，没有
迁移到这里。原因是它们彼此共享大量上下文（人物一致性、画风常量、禁则），
拆成独立 skill 目录会引入循环依赖，收益不抵风险。

`skills/` 目前为空，是为**新加的、可插拔的能力**准备的：一个 skill 应当能被
单独理解、单独测试，并且不修改 `app/` 里的任何文件就能被加载。

## 约定

- **纯函数优先。** handler 接收显式参数，不从全局读状态，这样测试不需要起服务。
- **不碰网络的部分单独抽出来。** 需要调用外部 API 的，实现放 handler，
  参数和解析放纯函数，后者可以离线测试。
- **不做隐式注册。** 新 skill 需要在 `app/platform/registry.py` 里显式声明，
  而不是靠扫描目录自动加载——自动加载会在打包时悄悄漏掉文件。
